# Keksdose — Deployment

Three deployment targets, all driven by the Aspire AppHost.

> **Platform note:** All demos were built and tested on Apple Silicon (arm64) with Podman as the container runtime. Your mileage may vary with Docker Desktop, Windows (WSL2/Hyper-V), or amd64 Linux — registry configuration, bridge network IPs, SSH key paths, and image architectures may need adjustment.

## Prerequisites

- [Aspire CLI](https://aspire.dev/docs/cli): `dotnet tool install -g aspire`
- Docker (for Docker Compose and Kamal)
- Helm + kubectl (for Kubernetes)
- [Kamal](https://kamal-deploy.org/): `gem install kamal`
- [Multipass](https://multipass.run) (for local Kamal testing): `brew install --cask multipass`

All commands run from the repository root.

## 1. Docker Compose

Generates a `docker-compose.yaml` from the AppHost resource graph.

```bash
./deploy/docker-compose/1-publish.sh   # generate artifacts → deploy/output/docker-compose/
./deploy/docker-compose/2-deploy.sh    # docker compose up
```

The generated `.env` file contains placeholders that must be filled before running.
Aspire generates the wiring but expects pre-built images — there is no `aspire build`
command yet. Use a local registry for local runs.

### Local registry setup (first time)

```bash
# Port 5000 is used by macOS AirPlay — use 5001 instead
docker run -d -p 5001:5000 --name local-registry --restart=always registry:2
```

#### Podman: allow insecure access to the local registry

The local registry serves plain HTTP. Two places need to be told to allow it.

**1. Host — for `docker push` / `dotnet publish /t:PublishContainer`**

Add to `~/.config/containers/registries.conf`:

```toml
[[registry]]
location = "localhost:5001"
insecure = true
```

**2. Podman machine — for `docker compose pull` (the compose engine runs inside the VM)**

```bash
podman machine ssh "sudo tee -a /etc/containers/registries.conf << 'EOF'

[[registry]]
location = \"localhost:5001\"
insecure = true
EOF"
```

Then reload the Podman API daemon so the change takes effect without a full machine restart:

```bash
podman machine ssh "sudo systemctl restart podman.socket"
```

**3. Docker credential helper**

If `~/.docker/config.json` contains `"credsStore": "desktop"` (left over from Docker Desktop),
remove that key — the `docker-credential-desktop` binary is not present and will cause
`docker compose pull` to fail with a credential error.

```json
{
  "auths": {}
}
```

### Build and push images

```bash
# .NET server — dotnet publish builds and pushes directly to the registry (no separate push needed)
dotnet publish src/CookieJar.Server/CookieJar.Server.csproj \
  /t:PublishContainer \
  -p ContainerRegistry=localhost:5001 \
  -p ContainerImageName=cookiejar-server \
  -p ContainerImageTag=latest

# Python sensor — uses the Dockerfile generated by aspire publish
docker build \
  -f deploy/output/docker-compose/cookie-sensor.Dockerfile \
  -t localhost:5001/cookiejar-cookie-sensor:latest \
  src/cookie-sensor
docker push localhost:5001/cookiejar-cookie-sensor:latest

# Vite frontend — multi-stage build (node → nginx), proxies /api/* to the server
docker build -t localhost:5001/cookiejar-frontend:latest src/frontend
docker push localhost:5001/cookiejar-frontend:latest
```

### Configure .env and run

`1-publish.sh` copies `deploy/.env.template` into the output directory after each publish.
Edit `deploy/.env.template` to change registry, passwords, or ports — it is committed to the repo.

## 2. Kubernetes / Helm

Generates a Helm chart from the AppHost resource graph.

```bash
./deploy/kubernetes/1-publish.sh   # generate Helm chart → deploy/output/helm/
./deploy/kubernetes/2-fix.sh       # patch Aspire-generated YAML (volume name dots)
./deploy/kubernetes/3-build.sh     # build images and load into minikube
./deploy/kubernetes/4-deploy.sh    # helm upgrade --install
```

## 3. Kamal (Custom Pipeline Step)

Kamal deploys Docker containers directly to bare-metal or cloud VMs via SSH.
No Kubernetes required.

```bash
./deploy/kamal/1-publish.sh   # generate artifacts → deploy/output/kamal/

# Configure
cp deploy/output/kamal/.kamal/secrets.example deploy/output/kamal/.kamal/secrets
# Edit secrets file — fill in SERVER_IP, passwords, connection strings

./deploy/kamal/2-build-push.sh  # build + push server, frontend, and cookie-sensor images
./deploy/kamal/3-deploy.sh setup  # first time: installs Docker on the server
./deploy/kamal/3-deploy.sh        # deploy / update (prints URLs when done)
```

After a successful deploy:

| Service | URL |
|---|---|
| API / backend | `http://<SERVER_IP>` (via kamal-proxy) |
| Frontend (React) | `http://<SERVER_IP>:3000` |
| Health check | `http://<SERVER_IP>/health` |

The Kamal config is generated by `KamalPipelineStep` — a custom `PipelineStep`
in `src/CookieJar.AppHost/Publishing/KamalPublisher.cs`. It walks the Aspire resource model
and maps resources to Kamal roles automatically:

- **ProjectResource** → main Kamal service (behind kamal-proxy, health-checked)
- **PostgresServerResource / RabbitMQServerResource** → accessories with bind-mount data dirs
- **ContainerResource with `EndpointAnnotation`** (frontend) → HTTP accessory, port exposed on host, `SERVER_URL=http://kamal-proxy` so nginx routes API calls through the Docker network
- **ContainerResource without `EndpointAnnotation`** (cookie-sensor) → worker accessory, no host port, connection strings injected from secrets

### Testing locally with Multipass

[Multipass](https://multipass.run) spins up a real Ubuntu VM locally in ~30 seconds,
making it ideal for testing Kamal without a remote server. `0-setup-vm.sh` generates
a dedicated SSH key (`~/.ssh/kamal-multipass`), starts a local container registry on
the host, and installs the key into the VM.

```bash
# Install multipass (macOS) — the pkg installer requires sudo,
# so run this in a real terminal (not via aspire/claude):
brew install --cask multipass

# One-time VM + local registry setup
./deploy/kamal/0-setup-vm.sh

# Generate artifacts
./deploy/kamal/1-publish.sh

# Copy and fill in secrets (use the IPs printed by 0-setup-vm.sh)
cp deploy/output/kamal/.kamal/secrets.example deploy/output/kamal/.kamal/secrets
$EDITOR deploy/output/kamal/.kamal/secrets

# Build and push the server image to the local registry
./deploy/kamal/2-build-push.sh

# First-time provisioning (installs Docker on the VM, ~2 min)
./deploy/kamal/3-deploy.sh setup

# Deploy
./deploy/kamal/3-deploy.sh
```

**Teardown:**

```bash
# Remove all containers from the VM
kamal remove --confirmed -c deploy/output/kamal/config/deploy.resolved.yml

# Destroy the VM
multipass stop kamal-demo
multipass delete kamal-demo && multipass purge

# Remove the local registry
podman rm -f local-registry
```
